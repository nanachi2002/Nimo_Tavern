What the AI actually receives

The AI never sees "your tavern". Every time you send a message, SillyTavern assembles one big block of text (the prompt) and sends it. A simplified picture:

[ System prompt ]            "You are roleplaying as {{char}}..."
[ Character card ]           description, personality, scenario
[ Your persona ]             who you are
[ World Info ]               only the lore entries triggered right now
[ Example messages ]         how the character talks
[ Chat history ]             as many recent messages as fit
[ Post-history / Author's note ]
→ then the AI writes the next message

Because the AI has no memory between requests, the whole thing is re-sent every time. That is why long chats cost more and why old messages eventually vanish.

What fits in the context window?

The context size is the maximum number of tokens in that prompt plus the reply. Fixed parts (system prompt, card, lore…) are always included; the chat history gets whatever space remains, and the oldest messages are dropped first. Try it:

How to give the AI a longer memory
  • Raise context size (if your model and budget allow). Bigger isn't always better: models get less accurate and more expensive with huge prompts.
  • Trim the character card and persona.
  • Use the Summarize extension to compress old events into a short recap.
  • Put lasting facts in a lorebook so they're only included when needed.

Advanced Formatting

The panel controls how the prompt text is laid out. It matters most for Text Completion (local models), where SillyTavern builds the raw text itself. Chat Completion providers build the final format themselves, so there you mostly use the Prompt Manager.

Context template (story string)

Defines the order and wrapping of the "fixed" parts. It uses placeholders:

{{#if system}}{{system}}
{{/if}}{{#if description}}{{description}}
{{/if}}{{#if personality}}{{char}}'s personality: {{personality}}
{{/if}}{{#if scenario}}Scenario: {{scenario}}
{{/if}}{{#if persona}}{{persona}}
{{/if}}

Most models work well with the default. Change it only if a model's documentation asks for a specific format.

Instruct template

Local models are trained on a particular chat format (ChatML, Llama-3, Mistral…): special tokens that mark who is speaking. If the instruct template doesn't match the model, replies get weird. Rule: pick the template that matches your model (it's usually named in the model's page) and turn Instruct Mode on.

SymptomProbable cause
Replies include odd tags like <|im_end|>Wrong or missing instruct template / stop sequence.
The AI writes your lines for youAdd your name as a stop string, or enable "Always add character's name to prompt".
Very short, bland repliesInstruct mode off for an instruct-tuned model, or response length too small.

System prompt

The first instruction block: tone, rules, formatting ("write in third person, 2–3 paragraphs, never speak for {{user}}"). SillyTavern ships several; you can edit or add your own. A character card may override it with its own system prompt (see Characters).

Tokens, measured

SillyTavern counts tokens with a tokenizer matching your model where it can, and shows counts in the card editor, the Prompt Manager and under each message. Counts are estimates for some providers, so leave a little headroom.

Tokenizing happens in your browser in NimoTavern: your text is never sent to the server to be counted.
