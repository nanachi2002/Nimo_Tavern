NimoTavern was built with one rule: the person running the server must not be able to read your chats, characters or API keys, even if they wanted to. Not "we promise not to look". Can't. This page explains how, in plain language. The technical page has the cryptography details and Verify it yourself shows how to check these claims in your own browser.

The big idea

Normal websites store your data in a form they can read, and protect it with their own promises. NimoTavern flips that: your browser locks your data before it leaves your device, using a key made from your password. The server only ever receives the locked box.

Where your password fits in

Your password never leaves your browser. It's stretched (with a deliberately slow, memory-hungry function called Argon2id) into two separate values:

  • A login proof: proves to the server that you know the password, without revealing it. The server stores only a hash of this proof.
  • An unlock key: opens a box containing your random data key. That box is stored on the server, but only you can open it.

What else NimoTavern does for privacy

  • No email, no phone, no real name. A username and a password are enough.
  • Provider requests go straight from your browser to the provider. Prompts and keys don't pass through NimoTavern by default.
  • No access logs, no third-party analytics, no ads, no trackers. The only third-party script is the Cloudflare Turnstile captcha on the sign-up page, which is there to stop bots.
  • IP addresses are not stored. They're only held in memory as keyed hashes, for rate limiting (minutes) and for counting unique daily visitors (the random salt is discarded every day, so the hashes can't be linked across days).
  • Anonymous usage counts. The operator sees plain daily numbers: page views, sign-ups, logins, unique visitors, and how many accounts were active that day, week or month. Nothing is stored per user or per IP, and the dedupe data for counting active accounts only exists for the current period and is then deleted. It's a count, never a list of who.
  • Strict browser protections: HTTPS only (with HSTS), a tight Content-Security-Policy that limits which servers the page can talk to, HttpOnly session cookies, no referrer leaks.
  • Open source (AGPL-3.0). Anyone can read the code and build their own copy.
  • You can take everything with you at any time, see Your data.

The honest limits

No system is magic. Here's exactly what encryption does not protect against:

You trust the code you're served

This is a web app: your browser downloads its JavaScript from the server each visit (with caching). A malicious operator could in theory publish modified code that steals keys. That's true of every web-based encrypted service. The defenses: the code is open source, the page is built from public source, and you can verify what's running. If you need zero trust in the host, run SillyTavern locally.

Your AI provider reads your prompts

Encryption protects your data at rest and from NimoTavern. When you chat, the provider you chose receives the conversation, otherwise it couldn't answer. Choose one whose policy you trust, or use a local model.

Your device is part of the security

While you're logged in, your keys are on your device (stored as non-exportable browser keys). Malware, a shared computer, or a stolen unlocked phone can expose them. Log out on shared devices and use a device lock.

Network infrastructure

NimoTavern sits behind Cloudflare for protection and speed. Like any such service, Cloudflare handles the encrypted connection and can see connection metadata (IP address, timing, request sizes). Because your data is encrypted before it's sent, what passes through is ciphertext.

A weak password is a weak lock

If someone obtains the encrypted data and then guesses your password offline, they could open it. Argon2id makes each guess slow and expensive, but a short or common password is still guessable. Use a long passphrase.

No password reset, by design

If you lose both your password and your 12-word recovery phrase, nobody can help you, including the admin. That's not a limitation we could "fix": it's the proof that we can't read your data.

Who is this for?

NimoTavern fits people who want a convenient hosted tavern and don't want the host to read their private roleplay, personas and keys. It sharply reduces what a hosted service can learn, and it protects you if the server is ever breached. For maximum assurance, verify the code yourself, or run SillyTavern on your own machine.
