Good security claims are testable. These checks use only your browser's built-in developer tools (press F12, or Ctrl+Shift+I; on Mac ⌘+Option+I). You don't need to be a programmer.

Check 1: what you upload is unreadable

  1. Log in and open the tavern. Open developer tools and go to the Network tab. Tick "Preserve log".
  2. Change something recognizable: send a message containing a unique word like zebra-banana-4412, or edit a persona.
  3. Look for requests to /api/nimo/blobs (type blobs in the filter box). Click one and open the Payload/Request tab.
  4. Search all requests for your unique word (the Network tab has a search: Ctrl+F inside it). You will find nothing. What you'll see is an id of hex characters and an opaque encrypted body.

Notice there are no requests carrying your message text to nimorp.lol at all. When you generate a reply, the request goes to your AI provider's domain (for example openrouter.ai), not to this site, unless you enabled the relay.

Check 2: your API key never goes to NimoTavern

  1. Stay on the Network tab and clear the log.
  2. Send a chat message. Find the request that generates the reply: its domain is your provider's.
  3. Open its Headers. The Authorization header with your key goes to that provider only. Filter by nimorp.lol: no request there contains your key or your prompt.

If you turned on Always use the relay in your Account page, requests to /api/nimo/relay will carry the prompt and key (to the server's memory, not disk). That's why it's opt-in.

Check 3: the local copy is encrypted too

  1. In developer tools open the Application tab (Chrome/Edge) or Storage (Firefox).
  2. Expand IndexedDB. You'll see nimo-cache and nimo-keys.
  3. Open nimo-cache → blobs: the values are encrypted bytes, not your chats.
  4. Open nimo-keys: the keys are stored as CryptoKey objects. Click one: it shows as an opaque object whose raw value can't be exported (non-extractable).

Check 4: logout really wipes it

Click Logout in the tavern, then look at IndexedDB again: the databases are gone. That's the local keys and the local encrypted copy deleted from that device.

Check 5: the code that runs the tavern

  • The Service Worker (Application → Service Workers) is SillyTavern's server code running locally. Its source is /nimo-sw.js; you can open it in a tab.
  • The page's security policy: in the Network tab click the main document and read the Content-Security-Policy response header. It lists exactly which servers the page may contact.
  • The source code is public under AGPL-3.0 (see the source link in the footer). The NimoTavern-specific part is in the nimo/ folder: shared/crypto.js contains all the key handling, and it's short enough to read in an afternoon.
  • Build it yourself. The repository README explains how to build the same bundles from source, so you can read what you built or host your own copy. (Builds aren’t guaranteed byte-for-byte identical, so compare behavior and code, not hashes.)

Check 6: what the server says about you

Open /api/nimo/auth/me in a tab while logged in. You'll see the data the server associates with your account: username, creation date, used bytes. That's it.

What these checks prove, and what they don't

They show that this version of the code, as served to you right now encrypts before sending and keeps keys local. They can't prove tomorrow's code will behave the same: that's the inherent limit of any web app, and the reason the source is public and the honest limitations are listed on the security page.
